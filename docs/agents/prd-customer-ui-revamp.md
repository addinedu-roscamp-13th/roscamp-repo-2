## Problem Statement

회원(도서관 이용자)이 쓰는 웹 UI가 시연 가능한 수준까지 왔지만, 실제로 써 보면 다음이 걸린다.

- **검색해도 뭘 눌러야 할지 모른다.** 검색 결과는 카드로 나열될 뿐 클릭해도 아무 일이 없고, 책 설명을 볼 방법이 없다. 결과가 몇십 개든 그냥 아래로 끝없이 이어진다.
- **책을 찾은 다음 요청까지 가는 길이 끊겨 있다.** 검색 화면에서 마음에 드는 책을 찾아도, 요청하려면 `/request`로 옮겨 가 같은 검색을 처음부터 다시 해야 한다.
- **지도에서 구역을 눌러도 책이 안 나온다.** "구역을 탭하면 그 서가의 책이 나와요"라고 안내해 놓고 항상 "등록된 책이 없습니다"가 뜬다.
- **내 정보 화면이 한눈에 안 들어온다.** 대출·요청·예약·읽고싶은책이 탭으로 갈려 있어 지금 내 상태를 알려면 네 번 눌러야 하고, 항목마다 큰 카드라 세로로 길다.
- **지난 이력을 지울 수 없다.** 반려되거나 삭제된 도서의 요청이 계속 쌓여서 최근 요청을 가린다.
- **추천 화면이 추천이 아니다.** "가장 핫한 책"이라며 `#1 #2` 순위를 붙여 놓았지만 실제 정렬 기준은 입고 역순이라 순위가 거짓말이다.
- **도서 요청 화면이 한 페이지에 다 펼쳐져 있다.** 1단계와 2단계가 동시에 보여서 지금 뭘 해야 하는지 흐리다.
- **쓰지 않는 기능이 자리를 차지한다.** 바코드·QR 스캐너와 OCR은 시연 시나리오에서 빠졌는데 설정 화면에 그대로 남아 있고, 백엔드는 부팅할 때마다 쓰지도 않는 OCR 모델을 메모리에 올린다.
- **LiBi bot이 대화만 한다.** 회원 UI에서 할 수 있는 일(요청·예약·연장·내 정보 조회)을 말로 시키면 못 하고, 책 추천만 겨우 한다.

## Solution

회원 UI를 "찾기 → 알아보기 → 요청하기 → 확인하기"가 끊기지 않는 하나의 흐름으로 다듬고, LiBi bot이 그 흐름의 모든 단계를 대신 실행할 수 있게 한다.

- 검색창에 입력하면 관련 도서가 **바로 아래에 뜨고**, 누르면 **바텀시트 상세**가 올라와 책 설명과 배치 상태를 보여준다. 거기서 바로 요청으로 넘어가면 **책이 이미 선택된 상태**로 요청 위저드 2단계에서 시작한다.
- 요청 화면은 **1단계 → [다음] → 2단계 → [요청 완료] → 3단계(내 요청)** 위저드가 되어 한 번에 한 가지만 묻는다.
- 내 정보는 **요약 대시보드**가 되어 카운터 네 개와 급한 것(연체·반납임박·승인대기)이 먼저 보이고, 나머지는 접어 둔다. 지난 요청 이력은 **개별·일괄 삭제**할 수 있다.
- 지도는 실제 주행 지도(`arte3`)를 배경으로 깔고 구역 박스를 도면처럼 마감하며, **구역을 누르면 그 서가의 책이 실제로 나온다**.
- 추천 화면은 **대출 횟수 기준 진짜 Top10**을 보여준다.
- 쓰지 않는 스캔·OCR 진입점은 걷어내고, 백엔드는 안 쓰는 모델을 더 이상 예열하지 않는다.
- LiBi bot에 **회원 기능 tool 레이어**를 붙여 "사피엔스 테이블 1번으로 가져다줘", "내 대출 뭐 있어?", "이거 예약해줘"가 실제로 실행되게 한다. 되돌리기 어려운 것은 **수정 가능한 확인 카드**를 거친다.

## User Stories

### 검색 · 발견

1. As a 회원, I want 홈 검색창에 글자를 넣으면 관련 도서가 그 자리 아래에 뜨는 것, so that 검색 페이지로 넘어가지 않고도 원하는 책이 있는지 바로 안다.
2. As a 회원, I want 서제스트 목록이 10권까지만 보이고 그보다 많으면 목록 안에서 스크롤되는 것, so that 화면이 검색 결과로 끝없이 밀려나지 않는다.
3. As a 회원, I want 서제스트의 책을 눌러 상세를 볼 수 있는 것, so that 제목만 보고 고르지 않아도 된다.
4. As a 회원, I want 검색 페이지 결과도 같은 규칙(10권 + 스크롤)으로 보이는 것, so that 두 화면의 동작이 어긋나지 않는다.
5. As a 회원, I want 타이핑을 멈춘 뒤에 검색이 실행되는 것, so that 한 글자마다 결과가 깜빡이지 않는다.
6. As a 회원, I want 검색 결과를 불러오는 동안 자리표시자가 보이는 것, so that 빈 화면을 보고 결과가 없다고 오해하지 않는다.
7. As a 회원, I want 검색 페이지에서 분야(문학·예술·과학·인문학·유아)로 걸러 볼 수 있는 것, so that 검색어가 떠오르지 않아도 둘러볼 수 있다.
8. As a 회원, I want 「도서 요청하기」와 「LiBi에게 물어보기」 안내가 검색 결과 위쪽에 있는 것, so that 결과를 끝까지 스크롤하지 않아도 다음 행동을 안다.
9. As a 회원, I want 검색창의 음성 버튼이 그대로 있는 것, so that 손으로 입력하기 어려울 때 말로 검색한다.
10. As a 회원, I want 홈의 큰 마이크로 말하면 그 말이 검색어가 되는 것, so that 지금까지 쓰던 방식이 그대로 유지된다.

### 도서 상세

11. As a 회원, I want 책을 누르면 화면이 통째로 바뀌는 대신 아래에서 시트가 올라오는 것, so that 보던 목록 자리를 잃지 않는다.
12. As a 회원, I want 상세에서 책 소개 글을 읽을 수 있는 것, so that 제목·표지만으로 판단하지 않아도 된다.
13. As a 회원, I want 상세에서 "누구에게 좋은 책인지" 태그를 볼 수 있는 것, so that 나에게 맞는 책인지 빨리 가늠한다.
14. As a 회원, I want 상세에서 그 책이 지금 도서관에 배치돼 있는지 알 수 있는 것, so that 헛걸음하지 않는다.
15. As a 회원, I want 대출 중인 책은 "대출 중"으로, 훼손·분실로 사서가 막아둔 책은 "대출 불가"로 구분되는 것, so that 왜 못 빌리는지 이해한다.
16. As a 회원, I want 상세에서 그 책이 어느 서가에 있는지 보는 것, so that 직접 가지러 갈 수도 있다.
17. As a 회원, I want 상세에서 바로 요청 화면으로 넘어가는 것, so that 요청하려고 같은 검색을 다시 하지 않는다.
18. As a 회원, I want 상세에서 넘어간 요청 화면에 그 책이 이미 골라져 있는 것, so that 방금 고른 책을 또 고르지 않는다.
19. As a 회원, I want 목록에서는 "재고 있음" 같은 뱃지가 사라지는 것, so that 목록이 덜 시끄럽다.
20. As a 회원, I want 목록에서도 그 책이 어느 서가인지는 계속 보이는 것, so that 위치 정보까지 잃지는 않는다.

### 도서 요청

21. As a 회원, I want 요청 화면이 한 번에 한 단계만 보여주는 것, so that 지금 뭘 해야 하는지 헷갈리지 않는다.
22. As a 회원, I want 1단계에서 책을 고르고 좌측 하단의 「다음」으로 넘어가는 것, so that 진행 방향이 분명하다.
23. As a 회원, I want 2단계에서 자리로 받을지 대여 신청할지 고르는 것, so that 목적에 맞게 받는다.
24. As a 회원, I want 자리로 받기를 고르면 테이블을 고를 수 있는 것, so that 내가 앉은 자리로 온다.
25. As a 회원, I want 2단계에서 요청을 마치면 3단계에서 내 요청 목록을 보는 것, so that 접수됐는지 바로 확인한다.
26. As a 회원, I want 상세에서 넘어온 경우 2단계부터 시작하는 것, so that 이미 고른 책을 다시 고르지 않는다.
27. As a 회원, I want 2단계에서 뒤로 가면 1단계에서 책을 다시 고를 수 있는 것, so that 잘못 골랐을 때 되돌린다.
28. As a 회원, I want 대출 중인 책은 요청 대신 예약으로 안내받는 것, so that 없는 책을 로봇이 찾으러 가지 않는다.
29. As a 회원, I want 요청 결과가 토스트로 뜨는 것, so that 접수됐는지 성공/실패가 분명하다.
30. As a 회원, I want 로그인하지 않은 상태에서 요청 화면에 들어가면 로그인으로 안내받는 것, so that 왜 안 되는지 알 수 있다.

71. As a 회원, I want 확인 카드를 취소할 수 있는 것, so that 원치 않으면 없던 일로 한다.
72. As a 회원, I want 로그인이 필요한 요청을 비로그인 상태로 하면 로그인 안내를 받는 것, so that 왜 안 되는지 안다.
73. As a 회원, I want 봇이 실행한 결과(접수 번호·자리·상태)를 대화에서 확인하는 것, so that 됐는지 다시 확인하러 가지 않는다.

### 문서 (코드 외)

74. As a 작성자, I want 요구사항 노트의 스크린샷이 Prismic CDN 이미지로 바뀌는 것, so that 옵시디언 밖에서도 노트를 읽을 수 있다.
75. As a 작성자, I want 로컬 스크린샷 원본이 정리되는 것, so that 볼트에 중복 파일이 남지 않는다.
76. As a 작성자, I want 이번에 확정된 내용이 그 노트에 반영되는 것, so that 다음에 볼 때 결정 사항이 남아 있다.

## Implementation Decisions

### 접근 방식

- **접근법 A(최소 변경 + 필요한 백엔드만 추가)** 를 채택한다. 이미 설치돼 있는 `@tanstack/react-query`를 도입해 데이터 계층을 갈아엎는 안은 기각했다 — 이번 요구사항 어디에도 캐싱 요구가 없고, 남이 작성한 고객 라우트 전부를 리팩터하는 위험이 이득보다 크다.
- 기존 데이터 패턴(`useEffect` + `fetchCatalog`)을 유지하고, 화면 간 중복은 **공용 컴포넌트 추출**로만 줄인다.

### 모듈 (신규/변경)

- **도서 카드/행 표시** — 검색 결과·서제스트·지도 구역 목록·요청 1단계·추천이 각각 자기 마크업을 들고 있다. 공용 표시 컴포넌트 하나로 모으고 "뱃지 없음 / 위치 표시 / 클릭 시 상세 열기"를 여기서 한 번만 정한다.
- **도서 상세 시트** — 바텀시트(`vaul` 기반 drawer)로 구현한다. 별도 라우트를 만들지 않는다. 목록이 이미 들고 있는 도서 객체를 그대로 받으므로 **단건 조회 API가 필요 없다**(`summary`·`for_whom`이 이미 목록 응답에 들어 있다).
- **가용 상태 판정** — `in_stock`과 `unavailable` 두 값을 받아 `배치중 / 대출 중 / 대출 불가` 세 상태 중 하나로 환산하는 순수 함수. 상세 시트·목록·봇 응답이 모두 이 함수를 쓴다.
- **디바운스 훅** — 입력값을 지정 시간 뒤에만 흘려보내는 작은 훅. 서제스트와 검색이 공유한다.
- **요청 위저드** — 요청 화면을 단계 상태(1/2/3)를 가진 흐름으로 바꾼다. URL 검색 파라미터로 책 id가 들어오면 1단계를 채운 채 2단계에서 시작한다.
- **내 정보 요약** — 네 종류 목록의 개수와 "급한 것"을 계산하는 부분을 표시와 분리한다. 섹션은 접힘 상태를 가진다.
- **회원 봇 도구 레이어** — 회원 API 각각을 LLM tool 스키마로 정의하고, 도구 이름 → 실제 호출로 잇는 실행기를 둔다. 도구마다 "조회형(즉시 실행) / 변경형(확인 필요)" 표시를 갖는다. 채팅 화면은 이 레이어를 호출만 하고 분기 로직을 갖지 않는다.
- **확인 카드** — 변경형 도구 호출을 사용자에게 보여주고, 인자 일부(자리, 요청 종류)를 고친 뒤 실행하거나 취소하게 하는 컴포넌트.
- **지도 구역 렌더링** — 기존 구역 박스 계산 로직은 유지하고 색·모서리·라벨·벽 표현만 도면 톤으로 손본다. 구역 좌표 계산 방식(waypoint 정점 → 경계 상자)은 바꾸지 않는다.

### API 계약 (백엔드 신규/변경)

- **인기 도서 조회** — 분야(선택)와 개수를 받아 대출 횟수 내림차순으로 도서를 준다. 동점은 안정적인 2차 기준으로 정렬한다. 대출 이력이 전혀 없는 상태에서도 빈 목록 대신 무언가는 나와야 한다(정렬만 무의미해질 뿐).
- **요청 이력 삭제** — 회원 인증으로 자기 요청 한 건을 지운다. 진행 중인 요청은 거부한다. 남의 요청은 조회조차 되지 않는다.
- **도서 응답 확장** — 고객용 도서 응답에 `unavailable`을 추가한다. 기존 필드는 그대로 두어 다른 화면이 깨지지 않게 한다.
- **부팅 예열 제거** — 앱 시작 시 OCR 모델을 예열하던 백그라운드 작업을 없앤다. OCR 엔드포인트 자체는 남긴다(로봇팔·사서 기능이 나중에 쓸 수 있다).

### 프론트엔드 변경 요약

- 삭제: 스캔 라우트, OCR 라우트, 설정의 스캔/인식 도구 섹션, 검색 화면의 미사용 미니맵, 미사용 음성 합성 함수, Lovable 서명 문구.
- 유지: 음성 인식(홈·검색), 언어 선택, QR 공유.
- 수정: 온보딩의 「음성으로 시작」이 실제로 인식을 시작하도록.
- 버그 수정: 지도 화면이 도서를 가져올 때 백엔드 상한을 넘는 개수를 요청해 항상 실패하던 문제. 상한 이내로 맞추고, 실패를 조용히 빈 목록으로 삼키지 않고 사용자에게 알린다.

### 지도 자산

- 주행 지도 `arte3.pgm`(63×108 점유격자)을 확대해 배경 PNG를 다시 만든다. 색은 프로젝트 팔레트(크림 바닥, 네이비 벽)에 맞춘다. 이미지 생성 작업은 codex에 위임할 수 있다.
- `arte3.yaml`과 `arte2.yaml`은 `origin`·`resolution`·크기가 동일하므로 **기존 waypoint 정규화 좌표는 그대로 유효**하다. 좌표 재생성은 하지 않는다.

### LLM 도구 호출

- 대상 모델은 로컬 Ollama의 `qwen3:1.7b`이며 `tools` capability를 지원한다. 다른 모델로 바꿔도 동작하도록 도구 정의는 모델에 종속되지 않게 둔다.
- 모델이 작아 오분류 가능성이 있으므로 **변경형 도구는 반드시 확인 카드를 거친다.** 조회형은 즉시 실행한다.
- 도구 실행은 기존 회원 API 클라이언트를 그대로 재사용한다. 봇 전용 백엔드 엔드포인트를 새로 만들지 않는다.
- 미로그인 상태에서 회원 도구가 선택되면 실행하지 않고 로그인 안내로 답한다.

## Testing Decisions

좋은 테스트는 **외부에서 관찰 가능한 동작**만 확인한다. 내부 함수 호출 순서나 상태 변수 이름이 아니라, "요청을 보내면 무엇이 돌아오는가", "이 입력에서 어떤 상태로 판정되는가"를 본다.

- **백엔드 (pytest, 기존 `aba_service/backend/tests/` 패턴을 따른다)**
  - 인기 도서 조회: 대출 횟수 순서대로 나오는가, 개수 상한이 지켜지는가, 분야 필터가 먹는가, 대출 이력이 없을 때도 안전한가.
  - 요청 이력 삭제: 자기 요청은 지워지는가, 남의 요청은 못 지우는가(404/403), 진행 중인 요청은 거부되는가, 비인증은 401인가.
  - 도서 응답: `unavailable`이 응답에 포함되는가, 기존 필드가 그대로인가.
  - 기존 테스트가 회귀하지 않는지 전체 스위트를 돌린다.
  - 프로젝트에 이미 있는 유사 테스트: 회원 알림 테스트, 배달 승인 테스트, 대출/반납 테스트.

- **프론트엔드**
  - 테스트 러너가 없고 이번 요구사항에 테스트 인프라 도입 요구가 없으므로 **린트 · 타입체크 · 프로덕션 빌드**를 게이트로 삼는다. 세 개가 모두 통과해야 완료로 본다.
  - 화면 동작은 **앱을 실제로 띄우고 화면별 스크린샷으로 확인**한다. 특히 "실동작 확인"이 요구된 항목(설정 정리 결과, 내 정보 데이터, 지도 구역 클릭, LiBi bot 응답)은 스크린샷을 증거로 남긴다.
  - 상태 판정 함수처럼 순수 로직은 타입 수준에서 전 분기를 강제하는 형태로 작성해 컴파일러가 누락을 잡게 한다.

- **런타임 검증 전제**: 백엔드(:8000)와 Ollama(:11434)가 떠 있어야 한다. 둘 다 현재 가동 중임을 확인했다.

## Out of Scope

- **로봇 하드웨어 명령 확장** — 지금 챗봇의 정규식 기반 모터·LCD·부저·로봇팔 명령은 손대지 않는다. 확장은 다음 사이클.
- **서버측 음성 인식(STT)/합성(TTS)** — 브라우저 내장 인식을 계속 쓴다. 서버 모델 도입은 하지 않는다.
- **LiBi bot에 마이크 추가** — 봇은 텍스트 입력만 받는다. 음성 도입은 나중에 검토.
- **관제(FMS) 챗봇** — `aba_fms_service` 쪽 챗봇은 별개 서비스이며 이번 범위가 아니다.
- **react-query 등 데이터 계층 도입** — 기각.
- **프론트엔드 테스트 프레임워크 도입** — 이번엔 하지 않는다.
- **OCR 엔드포인트 자체 삭제 / 의존성 제거** — 예열만 끄고 남긴다.
- **도서 배치 상태를 위한 DB 스키마 추가** — 기존 `in_stock`·`unavailable`로 충분하다.
- **딥링크 가능한 도서 상세 URL** — 상세는 시트라 고유 URL을 갖지 않는다.
- **다른 서비스**(`aba_controller`, `aba_fms_service`, `aba_ai_service`) 코드 변경.

## Further Notes

- 요청/승인 흐름의 의미는 기존 설계를 그대로 따른다: **자리로 받기(열람)** 는 승인 없이 로봇이 즉시 움직이고, **대여 신청**은 사서 승인 후에 움직인다. 봇의 확인 카드도 이 차이를 문구로 드러내야 한다.
- `unavailable`(훼손·분실)은 이미 요청·대출·승인 경로에서 차단 조건으로 쓰이고 있다. 이번에 바뀌는 것은 **고객 화면이 그 사실을 볼 수 있게 되는 것**뿐이다.
- 지도 화면의 "구역을 누르면 책이 나온다"가 지금까지 동작하지 않은 원인은 프론트가 백엔드 개수 상한을 넘는 값을 요청해 응답이 거부되고, 그 실패를 조용히 빈 목록으로 처리했기 때문이다. 같은 "실패를 빈 배열로 삼키는" 패턴이 도서 조회 클라이언트 전반에 있으므로, 최소한 사용자에게 보이는 경로에서는 실패와 "결과 없음"을 구분해야 한다.
- 커밋에 `Co-Authored-By` 트레일러를 넣지 않는다.
- git 조작(머지·푸시·브랜치 반영)은 사용자가 직접 수행한다. 구현 중 작업 브랜치 안에서의 커밋만 예외다.
