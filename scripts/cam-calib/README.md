# 카메라 캘리브레이션 (intrinsic) — picam + USB

노트북에서 **보면서** 찍는다. 로봇은 캡처만, 계산·저장은 노트북.
핸드아이 아님. `camera_matrix` / `dist_coeffs` 만 구한다.

```
로봇(Pi)                                   노트북
────────────────────────────────          ─────────────────────────
picam: rpicam-vid 480x360 -q80  ┐         화면 보며 배치 → SPACE 수집
USB  : V4L2 640x480             ┴MJPEG/HTTP→ calibrateCamera → npz 저장
```

## 딸깍 순서

```bash
# 0) 리허설 — 카메라 안 건드리고 노트북 화면이 뜨는지만 확인 (권장)
[Pi]   ./calib-pi.sh test
[노트북] ./calib-laptop.sh test <PI_IP> 0.038

# 1) picam (CSI)
[Pi]   ./calib-pi.sh picam
[노트북] ./calib-laptop.sh picam <PI_IP> <한칸실측_m>

# 2) USB
[Pi]   ./calib-pi.sh usb
[노트북] ./calib-laptop.sh usb <PI_IP> <한칸실측_m>
```

`calib-pi.sh` 가 노트북에서 칠 명령을 IP까지 채워서 출력한다. 그대로 복사하면 된다.

키: `SPACE` 수집 · `a` 자동수집 · `u` 취소 · `c` 계산+저장 · `q` 종료

**내부 코너 개수는 셀 필요 없다** — 보드를 화면에 통째로 보여주면 자동으로 감지해서
`내부 코너 5x5 (= 인쇄 칸 6x6)` 처럼 찍어준다. 틀리게 잡히면 직접 준다:

```bash
./calib-laptop.sh picam <PI_IP> 0.025 5x5     # 4번째 인자 = 내부 코너 가로x세로
```

> 내부 코너 = **사각형 4개가 만나는 점**. 칸 개수보다 가로·세로 각각 1 적다.
> 칸 개수와 헷갈려 잘못 넣으면 검출이 안 되거나, 더 나쁘게는 '부분 격자'가 잡혀
> 조용히 틀린 캘리브가 나온다. 그래서 자동 감지를 기본으로 뒀다.

## 저장 위치

| 소스 | 파일 | 읽는 곳 |
|---|---|---|
| picam | `robot_agent/config/camera_calib.npz` | `aruco_dock.py:49` — **코드 변경 없이 바로 적용** |
| usb | `robot_agent/config/camera_calib_usb.npz` | ⚠️ **아직 아무도 안 읽는다** (아래 참고) |

계산 성공 시 `<out>.points.npz` 에 원본 코너도 남는다 — 재촬영 없이 다시 계산할 수 있다.

## USB 캠 — 별도로 알아야 할 것

촬영 자체는 **picam 보다 쉽다.** 평범한 V4L2 라 libcamera 크롭 모드 문제도, CSI 단독 점유
문제도 없다. 대신 아래 3개가 걸린다.

### 0. 정말 필요한가

캘리브가 필요한 건 **미터 단위 자세**를 뽑을 때뿐이다(`solvePnP`).

| 용도 | 캘리브 |
|---|---|
| YOLO 사람 검출 / 추종 / ReID | ❌ 불필요. 바운딩 박스는 K 를 안 쓴다 |
| 화면 표시 / 녹화 | ❌ 불필요 |
| ArUco 로 거리 재기, 길이·좌표 측정 | ✅ 필요 |

> 2026-07-27 결정: **둘 다 캘리브한다.** USB 로도 미터를 쓸 예정.

### 1. 🔴 런타임 해상도가 고정돼 있지 않다

`aba_ai_service/.../perception_server.py:185` 의 `_camera_frames()` 는
`cv2.VideoCapture(index)` 만 하고 `CAP_PROP_FRAME_WIDTH/HEIGHT` 를 **하나도 안 준다.**
협상 결과는 USB 포트·커널·웹캠 펌웨어에 따라 달라질 수 있고, **해상도가 바뀌면 K 는 통째로 무효다.**

이 로봇 실측(2026-07-27):

```
/dev/video1  협상 결과: 640x480  YUYV(무압축)  30fps
지원 포맷   : MJPEG  1920x1080 … 640x480 / YUYV 1920x1080 … 640x480
```

`calib_stream_pi.py` 는 **640x480 을 명시 고정**하고, 다르게 잡히면 그 자리에서 중단한다.
런타임 쪽도 같은 값으로 고정해야 짝이 맞는다 — `cap.set()` 2줄이면 되지만
`aba_ai_service` 는 **다른 팀 서비스라 임의 수정 금지, 승인 후 반영할 것.**

### 2. 🔴 결과를 읽는 코드가 아직 없다

`aruco_dock.py:49` 의 `_CALIB_PATH` 가 전역 상수 1개라 카메라별로 갈리지 않는다.
`camera_calib_usb.npz` 는 저장만 되고 **아무도 안 읽는다.** 최소 변경은 이 정도다:

```python
# aruco_dock.py:49
_CALIB_DIR = Path(__file__).parent.parent.parent / "config"

# aruco_dock.py:120
def _load_calib(name: str = "camera_calib.npz") -> tuple[np.ndarray, np.ndarray] | None:
    path = _CALIB_DIR / name
    if not path.exists():
        return None
    try:
        data = np.load(str(path))
        return data["camera_matrix"], data["dist_coeffs"]
    except Exception:
        return None
```

기존 호출부(`:222`, `:386`)는 기본값이라 **picam 동작은 그대로**다.
USB 프레임을 쓰는 쪽에서만 `_load_calib("camera_calib_usb.npz")` 로 부른다.
추상화(카메라 클래스 등)는 만들지 않는다 — 인자 하나면 끝난다.

### 3. robot_agent 에는 USB 스트림이 없다

`camera_stream.py:425` 의 `camera = CameraManager()` 는 **모듈 전역 싱글톤 1개**이고
내부에 `_cam`(picamera2) / `_cap`(V4L2) 를 하나씩만 든다(`:41-42`).
V4L2 경로는 **두 번째 카메라가 아니라 picam 이 없을 때의 폴백**이다(`:274-282`).

→ `/api/robot/camera/snapshot` 은 **picam 전용**이다. USB 는 HTTP 로 못 가져온다.
이 캘리브 도구가 자체 스트리머(`calib_stream_pi.py`)를 쓰는 이유 중 하나다.

### 4. 인덱스·회전·부하

- **인덱스는 `/dev/video1`.** `/dev/video2` 는 같은 캠의 메타데이터 노드라 열면 실패한다.
  다르면 `USB_INDEX=2 ./calib-pi.sh usb`.
- `camera_sender.py --camera N` 은 `--rotate` 기본이 **0** 이다(picam 만 180). 전송 쪽에
  `--rotate 180` 을 붙였다면 그건 프레임 회전이므로 주점을 `cx→W-cx, cy→H-cy` 로 바꿔야 한다.
- 부하 실측: UDP 전송 시 **USB 33.7% / picam 21.6%**(1코어 기준, 4코어 환산 8.4% / 5.4%).
  USB 가 더 무거운 건 YUYV 무압축을 받아 BGR 변환 + JPEG 인코드까지 하기 때문이다.

### 5. AI 서버에서 미터를 쓸 때

`udp_video.py:80` 의 `resize_to_width(frame, 640)` 은 **순수 비율 리사이즈**(크롭 없음, `:21-26`)라
`K *= 640/W_capture` 스케일이 정확히 성립한다. USB 는 애초에 640 으로 캡처하므로
리사이즈가 no-op → **K 를 그대로 쓰면 된다.**

## 촬영 요령 (여기서 결과가 갈린다)

- **한 칸 크기는 자로 잰다.** 프린터 배율 때문에 25mm 설정이 25mm 가 아니다.
  틀리면 재투영오차는 멀쩡한데 **거리만 그 비율로 전부 틀어진다.**
- **딱딱한 판에 붙인다.** 종이가 휘면 그 오차가 그대로 K 에 들어간다. 가장 흔한 실패.
- **화면 구석을 채운다.** 우상단 3x3 격자가 보드 중심이 지나간 칸이다.
  중앙에서만 찍으면 왜곡계수가 0 근처로 나온다.
- **±30~40° 기울인 장면**을 상하·좌우 각각. 없으면 fx/fy 와 거리가 분리되지 않는다.
- 15fps 라 **프레임마다 완전히 정지**. 움직이면서 잡힌 코너는 그대로 오차다.
- 30~40장. 내부 코너가 적은 보드(예: 5x5 = 25점)면 한 장의 정보가 적으니 **40장 이상**.

### 한 칸이 작을 때 (예: 25mm · 5x5)

picam 은 480x360 뿐이라 보드가 작으면 가까이 가야 한다. 대략:

| 한 칸 | 보드 폭(6x6칸) | 30cm 거리 | 50cm 거리 |
|---|---|---|---|
| 25mm | 15cm | 한 칸 ≈ 35px (화면 폭의 44%) | 한 칸 ≈ 21px (26%) |
| 38mm | 23cm | 한 칸 ≈ 53px (67%) | 한 칸 ≈ 32px (40%) |

25mm 도 **30cm 안팎이면 검출은 된다.** 다만 CSI 는 고정초점이라 그 거리에서 흐릴 수 있으니
첫 화면에서 코너가 또렷한지 먼저 보고, 흐리면 35~40mm 로 다시 인쇄하는 편이 빠르다.
(보드가 화면을 꽉 채울 필요는 없다. 중요한 건 **보드를 화면 구석구석으로 옮기는 것**이다)

## 합격선

스크립트가 §5.1 수치 검증(RMS<0.5px, 왜곡≠0, 주점≠정중앙, fx≠fy)을 자동 출력한다.
**그러나 진짜 합격선은 실측 거리 오차 < 5%** 다. ArUco 마커를 자로 잰 거리(0.3/0.5/1.0m)에
두고 `z_m` 을 비교할 것. 재투영오차만으로는 보드 크기 오입력을 못 잡는다.

## 주의

- **CSI 는 한 프로세스만 잡는다.** `image-sender.sh --picamera` 나 `robot_agent` 가 떠 있으면
  `calib-pi.sh` 가 어떤 PID 를 꺼야 하는지 알려주고 멈춘다.
- **해상도가 곧 K 다.** picam 480x360 / USB 640x480 전용 결과다. 런타임 해상도가 바뀌면 무효.
  (AI 서버 쪽 `resize_to_width(640)` 은 순수 비율 리사이즈라 `K *= 640/W` 스케일이 성립한다)
- **`CAMERA_FLIP` 을 캘리브 후에 바꾸면 무효다.** `calib-pi.sh` 가 실기 `.env` 에서 읽어 맞춘다.
- `camera_calib.npz` 는 **git 추적 대상**이다. 로봇마다 값이 다르면 커밋 정책을 정해야 한다.

## 🔴 미해결 — 카메라 방향(상하반전). **부착 후에 확정할 것**

2026-07-27 기준 카메라를 아직 로봇에 부착하지 않았다. 방향은 부착해 봐야 알 수 있으므로
여기 적어두고 넘어간다.

**캘리브는 지금 해도 된다.** K·dist 는 렌즈·센서·해상도의 성질이라 어떻게 다느냐와 무관하다.
방향은 아래 조건만 나중에 맞추면 된다.

### 코드가 서로 모순돼 있다

| 경로 | 방향 처리 |
|---|---|
| `robot_agent` (rpicam-vid, `camera_stream.py:289`) | `CAMERA_FLIP=none` — 보정 없음 |
| `camera_sender.py --picamera` (`:75-80`) | `--rotate 180` 기본. 주석: "물리적으로 거꾸로 달림" |

여기에 수동 보정까지 얹혀 있다 — `aruco_dock_robot.py:56` 은 부호를 손으로 뒤집었고
(`ex>0` 인데 왼쪽으로 흐르는 오보정), `aruco_dock.py:188-190` 의 `_pose()` 는 `h` 가 오면
`img[:,1] = h - img[:,1]` 로 y 를 뒤집고 코너 순서를 `[3,2,1,0]` 으로 재배열한다.
**둘 다 방향 문제를 코드로 때운 흔적으로 보인다.** 방향을 확정하면 이것들을 재검토해야 한다.

### 부착 후 확인법

밝은 곳에서 위/아래가 분명한 것(천장 조명, 글자 있는 종이·폰 화면)을 비추고 한 장 찍는다.

```bash
./calib-pi.sh picam &            # 런타임과 같은 파이프라인
curl -s -o /tmp/o.jpg http://localhost:8099/snapshot
```

### 결과별 조치

| 찍힌 모습 | 조치 |
|---|---|
| 똑바로 | `CAMERA_FLIP=none` 유지. 그대로 캘리브 값 사용 |
| 뒤집힘 → **소프트웨어**로 돌릴 때 (`camera_sender --rotate 180`) | 회전은 프레임 전체를 도는 것이므로 **주점도 같이 돌아간다**. 회전된 영상에 쓰려면 `cx→W-cx, cy→H-cy` |
| 뒤집힘 → **하드웨어 flip** 을 켤 때 (`CAMERA_FLIP=vertical/both`) | 캘리브 당시와 파이프라인이 달라진다. `cx/cy` 를 위와 같이 변환하거나 다시 찍는 게 안전 |

⚠️ **캘리브 이후에 `CAMERA_FLIP` 을 바꾸면 그 캘리브는 무효다.** `calib-pi.sh` 는 실기 `.env` 에서
읽어 맞추므로, 값을 바꿨으면 캘리브도 다시 해야 한다.
